Elasticsearch

2025-06-27

什么是elasticsearch

elasticsearch是一款非常强大的开源搜索引擎技术，可以帮助我们从海量数据中快速找到需要的内容。

  1. elasticsearch是elastic stack的核心，负责存储、搜索、分析数据。elasticsearch底层实现是基于Lucene技术
  2. Kibana是数据可视化的组件，也就是展示搜索出来的数据。
  3. Logstash、Beats是负责数据抓取的组件。Lucene是一个Java语言的搜索引擎类库(其实就是一个jar包），是Apache公司的顶级项目，由DougCutting于1999年研发。Lucene官网：https：//lucene.apache.org
    Lucene的优势
    ● 易扩展
    ● 高性能(基于倒排索引)
    Lucene的缺点
    ● 只限于Java语言开发
    ● 学习曲线陡峭，也就是API复杂不利于学习
    ● 不支持水平扩展，只负责如何实现搜索，不支持高并发、集群扩展
    由于Lucene的缺点，诞生出了elasticsearch，与Lucene相比，elasticsearch（基于Lucene，且Compass是elasticsearch的前身)具有以下优点：
    ● 支持分布式，可水平扩展
    ● 提供Restful接口，可被任何语言调用
    ● elasticsearch的核心技术是倒排索引。

倒排索引

传统数据库（例如MvSQL）采用正向索引，例如给下表(tb_goods)中的id创建索引：
id Title Price
1 小米手机 3499
2 华为手机 5999
3 华为小米充电器 39
4 小米手环 49
... ... ...
搜索手机：select * from tb_goods where title like '%手机%';
需要逐条数据扫描，判断是否包含‘手机’，是的话才会存入结果集，否则丢弃。虽然最后能找到满足条件的数据，但是一条条数据进行比对，太低效，如果数据量庞大，那么搜索效率就会成为瓶颈，这就是正向索引的弊端。
elasticsearch采用倒排索引，例如给上表(tb_goods)中的id创建索引：
词条(term) 文档id
小米 1，3，4
手机 1，2
华为 2，3
充电器 3
手环 4
文档（document）：每条数据就是一个文档
词条（term）：文档按照语义分成的词语
搜索‘华为手机’，流程：

  1. 分词，得到：‘华为’、‘手机’两个词条
  2. 去词条列表查询文档id，得到每个词条所在文档id：华为：2，3；手机：1，2
  3. 根据文档id查询文档，得到id为1，2，3的文档
    总结
    1、正向索引：基于文档id来创建索引。查询词条时必须先找到文档，而后判断是否包含词条
    2、倒排索引：对文档内容进行分词，对词条创建索引1，并记录词条所在文档的信息。查询时先根据词条去查询文
    档id，然后获取到文档

elasticsearch对比mysql

elasticsearch是面向文档存储的，可以是数据库中的一条商品数据，一个订单信息。注意elasticsearch的文档是以json形式存储的，也就是说，我们把数据(也叫文档)存储进elasticsearch时，这些文档数据就会自动被序列化为json格式，然后才存储进elasticsearch
MySQL Elasticsearch 说明
Table Index 索引(index)，就是文档的集合，类似数据库的表(table)
Row Document 文档(Document)，就是一条条的数据，类似数据库中的行(Row)。这里的文档都是JSON格式
Column Field 字段(Field)，就是JSON文档中的字段，类似数据库中的列(Column)
Schema Mapping Mapping(映射)是索引中文档的约束，例如字段类型约束。类似数据库的表结构(Schema)
SQL DSL DSL是elasticsearch提供的JSON风格的请求语句，用来操作elasticsearch，实现CRUD
1、MySQL： 擅长事务类型的操作，可以确保数据的安全和一致性。一般用于增删改
2、Elasticsearch： 擅长海量数据的搜索、分析、计算。一般用于查询
两者是互补关系，不是替代关系，因此在业务系统架构中，两者都会存在，让用户在MySQL里面增删改数据，然后MySQL把数据同步给elasticsearch，用户要查询的时候，就在elasticsearch里面进行查询

安装elasticsearch

安装elasticsearch，简称es
第一步： 创建网络。因为我们还需要部署kibana容器，因此需要让es和kibana容器互联
systemctl start docker#启动docker服务
docker networkcreatees-net#创建一个网络，名字是es-net
第二步： 加载es镜像。采用elasticsearch的7.12.1版本的镜像，这个镜像体积有800多MB，所以需要在Windows上下载链接安装包，下载下来是一个es的镜像tar包，然后传到CentOS7的/root目录
第三步： 把在CentOS7的/root目录的es镜像，导入到docker
docker load -i es.tar
第四步： 创建并运行es容器，容器名称就叫es。在docker(也叫Docker大容器、Docker主机、宿主机)，根据es镜像来创建es容器
docker run -d
--name es
-e "ES_JAVA_0PTS=-Xms512m -Xmx512m"
-e "discovery.type=single-node"
-V es-data：/usr/share/elasticsearch/data
-V es-plugins：/usr/share/elasticsearch/plugins
--privileged
--network es-net
-p 9200：9200
-p 9300：9300
elasticsearch：7.12.1
命令解释：
● -e "cluster.name=es-docker-cluster"：设置集群名称
● -e "http.host=0.0.0.0"：监听的地址，可以外网访问
● -e "ES_JAVA_OPTS=-Xms512m -Xmx512m"：内存大小，不能低于512
● -e "discovery.type=single-node"：运行模式，例如非集群模式
● -v es-data：/usr/share/elasticsearch/data：挂载数据卷，绑定es的数据目录
● -v es-logs：/usr/share/elasticsearch/logs：挂载数据卷，绑定es的日志目录
● -v es-plugins：/usr/share/elasticsearch/plugins：挂载数据卷，绑定es的插件目录
● --privileged：授予数据卷访问权
● --network es-net ：加入一个名为es-net的网络中
● -p 9200：9200：端口映射配置，向外暴露的http请求端口，用于用户访问
● -p 9300：9300：端口映射配置，是es容器各个节点之间互相访问的端口，由于我们是单节点部署，所以用不到
● elasticsearch：7.12.1： 镜像名称，要把哪个镜像创建为容器，注意带版本号
然后，在浏览器中输入：http：//你的ip地址：9200 即可看到elasticsearch的响应结果

kibana 的作用： 让我们非常方便的去编写elasticsearch中的DSL语句，从而去操作elasticsearch
第一步： 确保docker是启动的
第二步： 加载kibana镜像。这个镜像体积有1.04G，所以需要在Windows上下载链接安装包，下载下来是一个kibana.tar文件，然后传到CentOS7的/root目录
第三步： 把在CentOS7的/root目录的kibana镜像，导入到docker
docker load -i kibana.tar

docker run -d
--name kibana
-e ELASTICSEARCH_H0STS=http：//es：9200
--network=es-net
-p 5601：5601

#-e ELASTICSEARCH_HOSTS：设置elasticsearch的地址，因为kibana已经与elasticsearch在一个网络，因此可以用容器名直接访问#elasticsearch
#-p5601：5601：端口映射配置，向外暴露的http请求端口，用于用户访问
第五步： kibana启动一般比较慢，需要多等待一会，可以通过命令
dockerlogs-fkibana#查看运行日志，当查看到下面的日志，说明成功
第六步： 测试。在浏览器中输入：http：//你的ip地址：5601 即可看到elasticsearch的响应结果

安装IK分词器
IK分词器官网： https：//github.com/medcl/elasticsearch-analysis-ik。注意elasticsearch、kibana、IK分词器，这三者通常是一起使用的
es在创建倒排索引时，需要对文档进行分词。在搜索时，需要对用户输入的内容进行分词。但默认的分词规则不支持中文处理，默认是只支持对英文进行分词，但是在正常业务中，我们需要处理的文档大多是中文，所以我们需要对中文进行分词，所以就需要安装IK分词器

  1. 第一步： 我们在 '安装elasticsearch' 创建elasticsearch容器时，指定了数据卷目录，其中有个数据卷指定了自定义名称为es-plugins，表示存放插件的数据卷，我们使用inspect命令把es-plugins数据卷的路径信息查询出来
  2. 第二步： 下载ik.zip压缩包到Windows，下载后解压出来是ik文件夹，根据上面查询出来的es-plugins数据卷的路径，把ik文件夹上传到CentOS7的 /var/lib/docker/volumes/es-plugins/_data 目录
  3. 第三步： 重启elasticsearch容器，我们在 '安装elasticsearch' 创建elasticsearch容器时，指定了自定义容器名称为es
  4. 第四步： 查看elasticsearch容器的启动日志
  5. 第五步： 确保elasticsearch、kibana已正常运行
  6. 第六步： 测试。在浏览器中输入：http：//你的ip地址：5601 即可看到elasticsearch的响应结果
    IK分词器包含两种模式：
    ● ik_smart：最少切分，根据语义分词，正常分词
    ● ik_max_word：最细切分，也是根据语义分词，分的词语更多，更细
    IK分词器的词典扩展和停用
    Ik分词器的分词，底层是一个字典，在字典里面会有各种各样的词语，当ik分词器需要对分词文本进行分词时，ik分词器就会拿着这个文本(乱拆成多个词或词语)，一个个去字典里面匹配，如果能匹配到，证明某个词(乱拆成多个词或词语)是词，就把这个证明后的词分出来，作为一个词。
    第一个问题： 字典的分词效果是有限的，只能对日常生活中常见的语义相关的词，进行分词，由于字典的词汇量少，所以我们需要对字典进行扩展。
    第二个问题： 字典的分词效果往往存在违禁词，我们不希望IK分词器能匹配并成功把词典里的违禁词作为分词，解决： 禁用某些敏感词条
    解决：
    1、要拓展或禁用ik分词器的词库，只需要修改一个分词器目录中的config目录中的IKAnalyzer.cfg.xml文件
    2、在config目录新建myext.dic文件，写入自己想要的特定词，也就是扩展词。新建mystopword.dic文件，写入自己想要禁用的特定词，也就是不参与分词的词
    3、重新启动elasticsearch、kibana
    4、测试。在浏览器中输入：http：//你的ip地址：5601 即可看到elasticsearch的响应结果

ES-DSL操作文档

  1. mapping属性
    mapping属性的官方文档： https：//elastic.co/guide/en/elasticsearch/reference/current/index.html
    MySQL Elasticsearch 说明
    Table Index 索引(index)，就是文档的集合，类似数据库的表(table)
    Row Document 文档(Document)，就是一条条的数据，类似数据库中的行(Row)。这里的文档都是JSON格式
    Column Field 字段(Field)，就是JSON文档中的字段，类似数据库中的列(Column)
    Schema Mapping Mapping(映射)是索引中文档的约束，例如字段类型约束。类似数据库的表结构(Schema)
    SQL DSL DSL是elasticsearch提供的JSON风格的请求语句，用来操作elasticsearch，实现CRUD
    mapping是对索引库中文档(es中的文档是json风格)的约束，常见的mapping属性包括如下
    ● type：字段数据类型
    ○ 字符串(分两种)： text（可分词的文本）、keyword（精确值，例如：品牌、国家、ip地址等不可分词的词语）
    ○ 数值： long、integer、short、byte、double、float
    ○ 布尔： boolean
    ○ 日期： date
    ○ 对象：object
    ● index：是否创建倒排索引，默认为true(也就是可参与分词搜索)，改成false的话，别人就搜索不到你
    ● analyzer：分词器，当字段类型是text时必须指定分词器。如果字段类型是keyword，那么不需要指定分词器
    ● properties：子字段，也就是属性和子属性

  2. 创建索引库
    创建索引库和mapping的DSL语法如下，需通过Kibana的Dev Tools（访问http：//你的ip地址：5601）发送请求。以下是一个完整的示例：
    PUT /索引库名
    {
    "mappings"： {
    "properties"： {
    "name"： { "type"： "text", "analyzer"： "ik_max_word" }, // text类型，指定中文分词器
    "age"： { "type"： "integer" }, // 数值类型
    "email"： { "type"： "keyword" }, // 精确值，不分词
    "address"： {
    "type"： "object", // 对象类型
    "properties"： {
    "city"： { "type"： "keyword" },
    "street"： { "type"： "text" }
    }
    },
    "is_active"： { "type"： "boolean", "index"： true } // 布尔类型，可搜索
    }
    }
    }
    注意：
    ● 确保删除注释后再发送请求。
    ● analyzer 只对text类型字段有效，中文场景建议使用ik_max_word（需安装IK分词器）。
    ● 如果索引已存在，重复创建会报错。

  3. 查询、修改、删除索引库

  4. 查询索引库语法
    ● 查询所有索引：
    GET /_cat/indices?v
    返回所有索引的详细信息，包括状态、文档数量等。
    ● 查询指定索引的mapping：
    GET /索引库名/_mapping
    返回索引库名索引的mapping定义。

  5. 往索引库添加新字段
    索引库的mapping无法直接修改，但可以添加新字段。语法如下：
    PUT /索引库名/_mapping
    {
    "properties"： {
    "new_field"： {
    "type"： "keyword"
    }
    }
    }
    注意：
    ● 新字段名不能与已有字段重复，否则报错。
    ● 已有的字段类型无法修改（如text不能改为keyword）。

  6. 删除索引库语法
    删除指定索引库：
    DELETE /索引库名
    注意：
    ● 删除操作不可恢复，谨慎使用。
    ● 如果索引不存在，ES会返回错误。

  7. 新增、查询、删除文档

  8. 新增文档的DSL语法
    添加文档到指定索引库，文档ID可手动指定或由ES自动生成：
    POST /索引库名/_doc/1
    {
    "name"： "张三",
    "age"： 25,
    "email"： "zhangsan@example.com",
    "address"： {
    "city"： "北京",
    "street"： "朝阳路"
    },
    "is_active"： true
    }
    注意：
    ● 如果省略文档ID（如用POST /索引库名/_doc），ES会生成随机ID。
    ● 建议手动指定ID，便于后续操作。

  9. 查询文档
    查询指定文档：
    GET /索引库名/_doc/1
    返回文档内容，包括_source字段中的JSON数据。

  10. 删除文档
    删除指定文档：
    DELETE /索引库名/_doc/1
    注意：
    ● 删除后不可恢复。
    ● 如果文档ID不存在，ES会返回not_found。

  11. 修改文档
    方式一：全量修改
    全量修改会覆盖旧文档，等同于删除旧文档并添加新文档。语法如下：
    PUT /索引库名/_doc/1
    {
    "name"： "张三",
    "age"： 26, // 修改年龄
    "email"： "zhangsan@example.com",
    "address"： {
    "city"： "北京",
    "street"： "朝阳路"
    },
    "is_active"： true
    }
    注意：
    ● 必须包含所有字段，否则未指定的字段会被删除。
    ● 如果文档ID不存在，此操作会变为新增。
    方式二：增量修改
    只修改指定字段的值，保留其他字段不变。语法如下：
    POST /索引库名/_update/1
    {
    "doc"： {
    "age"： 26 // 只修改年龄
    }
    }
    注意：
    ● 使用_update接口，仅更新指定字段。
    ● 如果文档ID不存在，此操作会变为新增（需确保mapping支持新字段）。

  2. Hotel 数据结构分析
    MySQL 数据结构（基于 tb_hotel.sql）：
    字段名 数据类型 说明
    id BIGINT 主键，酒店ID
    name VARCHAR 酒店名称
    brand VARCHAR 酒店品牌
    address VARCHAR 酒店地址
    price DECIMAL 价格
    star INT 星级
    city VARCHAR 城市
    latitude DECIMAL 纬度
    longitude DECIMAL 经度
    Elasticsearch Mapping（基于 MySQL 结构）：
    {
    "mappings"： {
    "properties"： {
    "id"： { "type"： "keyword" }, // 精确值，不分词
    "name"： { "type"： "text", "analyzer"： "ik_max_word" }, // 可分词，中文分词器

    "star"： { "type"： "integer" }, // 整数
    "city"： { "type"： "keyword" }, // 精确值

    }
    }
    }
    注意：
    ● latitude 和 longitude 合并为 location 字段，使用 geo_point 类型，格式为 { "lat"： 纬度, "lon"： 经度 }。
    ● 中文字段（如 name, address）使用 IK 分词器（需安装）。
    ● index： true 为默认值，可省略。

ES-DSL查询文档

官方文档： Elasticsearch Query DSL
一、查询类型概览

  1. 查询所有（match_all）
    ● 查询所有文档，一般用于测试或初步查看数据结构。
    ● 示例：
    {
    "query"： {
    "match_all"： {}
    }
    }

  2. 全文检索查询（Full Text Queries）
    2.1 match 查询
    ● 对输入进行分词，再匹配倒排索引。
    {
    "query"： {
    "match"： {
    "xxALL"： "如家"
    }
    }
    }
    2.2 multi_match 查询
    ● 可同时匹配多个字段。
    {
    "query"： {
    "multi_match"： {
    "query"： "如家",
    "fields"： ["name", "brand", "business"]
    }
    }
    }

  3. 精确查询（Term-level Queries）
    3.1 term 查询
    ● 不分词，直接匹配 keyword、数值、布尔值、日期字段等。
    {
    "query"： {
    "term"： {
    "city"： "上海"
    }
    }
    }
    3.2 range 查询
    ● 范围匹配
    {
    "query"： {
    "range"： {
    "price"： {
    "gte"： 200,
    "lte"： 300
    }
    }
    }
    }

  4. 地理位置查询（Geo Queries）
    geo_distance 查询
    ● 基于经纬度查找一定范围内的数据。
    {
    "query"： {
    "geo_distance"： {
    "distance"： "15km",
    "xxlocation"： {
    "lat"： 31.25,
    "lon"： 121.5
    }
    }
    }
    }
    geo_bounding_box 查询
    ● 查询geo_point值落在某个矩形范围的所有文档，用两个点来围成的矩形范围
    {
    "query"： {
    "geo_bounding_box"： {
    "字段名": {
    "top_left": {
    "lat": 31.1,
    "lon": 121.5
    },
    "bottom_right": {
    "lat": 30.9,
    "lon": 121.7
    }
    }
    }
    }
    }

  5. 复合查询（Compound Queries）
    5.1 function_score 查询
    ● 控制文档得分以影响排名。
    {
    "query"： {
    "function_score"： {
    "query"： {
    "match"： {
    "name"： "如家"
    }
    },
    "functions"： [
    {
    "filter"： { "term"： { "city"： "北京" } },
    "weight"： 5
    }
    ]
    }
    }
    }
    5.2 bool 查询
    ● 布尔组合查询（must/should/must_not/filter）
    {
    "query"： {
    "bool"： {
    "must"： [
    { "match"： { "name"： "如家" } }
    ],
    "filter"： [
    { "range"： { "price"： { "lte"： 400 } } },
    {
    "geo_distance"： {
    "distance"： "10km",
    "xxlocation"： {
    "lat"： 31.21,
    "lon"： 121.5
    }
    }
    }
    ]
    }
    }
    }

二、搜索结果处理

  1. 排序（sort）
    ● 支持按 keyword、数值、地理位置、日期排序。
    {
    "sort"： [
    { "_score"： "desc" },
    { "price"： "asc" }
    ]
    }
    地理排序示例：
    {
    "sort"： [
    {
    "_geo_distance"： {
    "xxlocation"： {
    "lat"： 28.28811,
    "lon"： 121.66053
    },
    "order"： "asc",
    "unit"： "km"
    }
    }
    ]
    }
  2. 分页（from + size）
    {
    "from"： 100,
    "size"： 20,
    "query"： { ... },
    "sort"： [ { "price"： "asc" } ]
    }
    深度分页解决方案
    ● search_after：基于上次排序值翻页（只能向后翻）
    ● scroll：快照分页（内存消耗大，不实时，已不推荐）
  3. 高亮显示（highlight）
    {
    "query"： {
    "match"： {
    "name"： "如家"
    }
    },
    "highlight"： {
    "fields"： {
    "name"： {}
    }
    }
    }

三、总结
● 查询类型：match、multi_match、term、range、geo_distance、function_score、bool
● 结果处理：排序、分页、高亮
● 深度分页推荐使用 search_after
● 可通过 _score 或 weight 控制相关性排名

    .map(Hit：：source)
    .collect(Collectors.toList());
    }
    ● 调用方式：

    client.search(s -> s
    .index("gghotel")
    .query(q -> q.range(r -> r
    .field("price")
    .gte(JsonData.of(200))
    .lte(JsonData.of(500)))),
    HotelDoc.class
    );

  5. 布尔查询（bool）
    ● 组合 must + filter：
    client.search(s -> s
    .index("gghotel")
    .query(q -> q.bool(b -> b
    .must(m -> m.term(t -> t.field("city").value(v -> v.stringValue("上海"))))

    )),

    );

    )),
    HotelDoc.class

  7. 排序与分页
    ● 分页：
    .from(0)
    .size(10)
    ● 排序：
    .sort(sort -> sort.field(f -> f

    .order(SortOrder.Asc)))

    );

  8. 高亮显示
    ● 设置高亮字段：
    client.search(s -> s
    .index("gghotel")
    .query(q -> q.match(m -> m.field("name").query("如家")))
    .highlight(h -> h
    .fields("name", f -> f
    .preTags("")

ES-es集群

  1. 集群核心概念补充
    ● 集群（Cluster）：由多个节点（Node）组成，对外表现为一个统一的搜索与索引服务。
    ● 节点（Node）：运行 Elasticsearch 的实例，每个节点有唯一名称。
    ● 索引（Index）：类似关系型数据库中的表，是逻辑上的文档集合。
    ● 文档（Document）：数据记录的最小单位，类似关系型数据库中的一行数据。
    ● 分片（Shard）：ES 为了实现横向扩展将一个索引的数据分成若干物理单元，每个分片可以独立存储、查询。

  2. 节点角色详解
    节点角色 配置项 说明
    Master node.master=true 负责集群管理（元数据、分片分配等），一个集群只能有一个主节点。
    Data node.data=true 存储数据，执行实际的 CRUD、搜索和聚合操作。
    Ingest node.ingest=true 负责预处理文档，如管道处理、日志解析等。
    Coordinating 所有为 false 请求协调节点，不存储数据、不选主，负责接收请求并分发到数据节点。
    建议：部署集群时，建议分离 Master 和 Data 节点，保证主节点稳定性。

  3. 分片与副本机制深入理解
    ● 主分片（Primary Shard）：写入数据的起点，每条数据只会进入一个主分片。
    ● 副本分片（Replica Shard）：主分片的备份，不直接写入，但可读取。
    ● 分片分配公式：
    shard = hash(_id) % number_of_primary_shards
    ● 副本作用：
    ○ 提升查询能力（副本也能查询）。
    ○ 宕机时提供容错（主分片宕机，副本可晋升为主分片）。

  4. 分片分配过程细节
    新增文档流程（简化）：

  5. 请求到达协调节点。

  6. 协调节点根据 _id 和主分片数选择目标主分片。

  7. 将写请求转发到主分片所在节点。

  8. 主分片写成功后同步给所有副本分片。
    查询文档流程：

  9. 请求到协调节点。

  10. 协调节点将查询请求转发给所有分片（主或副本均可）。

  11. 汇总返回结果并排序分页，返回给用户。

  12. 故障转移与数据恢复机制
    ● Master 节点负责监控整个集群的健康状态。
    ● 当某个节点宕机后，主节点会重新分配分片副本，确保数据不丢失。
    ● 副本晋升机制：如果主分片不可用，副本自动晋升为新的主分片。
    ● 节点恢复后，主节点会尝试将原分片再迁回恢复节点（若配置允许）。
    温馨提示：在生产环境下，推荐设置副本数至少为 1，确保高可用。

  13. 避免脑裂和主节点选举机制
    ● 脑裂现象：网络异常或主节点宕机，多个候选节点各自认为自己是主节点，造成集群状态不一致。
    ● 选举机制（Zen Discovery）：
    ○ 需要超过半数候选节点的选票才能成为主节点。
    ○ 最好使用奇数个 master-eligible 节点（如 3 个），避免 50% 投票僵局。
    ● ES 7.0 以后：
    ○ 自动启用了基于 quorum（多数派）的主节点选举策略。
    ○ 不再手动设置 discovery.zen.minimum_master_nodes。

  14. Cerebro 工具优势总结
    ● 类似于 Kibana 的集群可视化管理工具。
    ● 可监控节点健康、分片状态、磁盘使用率等。
    ● 支持直接执行 DSL（但不支持复杂图表或 Kibana 的监控分析功能）。

  15. 集群部署建议
    ● 生产集群一般配置建议：
    ○ 3 个 Master-eligible 节点（防止脑裂）。
    ○ 2-3 个 Data 节点（根据存储和查询压力增减）。
    ○ 分离 master 和 data 节点，避免角色冲突。
    ○ 使用外置的协调节点处理所有查询/写入请求，避免 master 过载。
    ● 磁盘容量规划：
    ○ 单节点使用磁盘最好不超过 70%，留有空间给 shard 迁移。
