Neo4j图数据库底层存储

2025-07-13

一、文章主旨归纳

Neo4j 的底层存储并不是传统的“按边切”或“按点切”的方式，而是构建了一个以 ID 为中心、可直接定位到磁盘偏移位置的定长存储系统，通过这种方式实现了免索引邻接（Index-Free Adjacency），大幅提升图遍历性能。

二、基本概念解读

1. 属性图（Property Graph）

Neo4j 使用的是Labeled Property Graph，图由：

  • 节点（Node）：可以带多个标签（Label）
  • 关系（Relationship）：有方向、有类型（Type）
  • 属性（Property）：可以存在于节点和关系上，键值对形式

这种模型非常适合表示社交网络、知识图谱等连接性强的数据。

2. 按边切 vs 按点切 vs 原生图存储

  • 按边切（Edge-centric）：
    • 关系和两个端点绑定，两份存储副本（起点和终点各存一份）
    • 多见于 OLTP 图数据库，如 JanusGraph、HugeGraph
  • 按点切（Vertex-centric）：
    • 把所有边聚合在节点中，适合批量计算（OLAP）
  • Neo4j 的方式：原生图存储（Native Graph Storage）
    • 点、边、属性各自独立定长存储
    • 所有实体通过 ID 组织结构，并通过 ID 定位 → 无需索引定位关系（即免索引邻接）

三、Neo4j 磁盘结构

点结构（15 字节）

字段 说明
1 byte inUse标志 + 高位的 nextRel 和 nextProp
4 bytes nextRelId：第一条边 ID
4 bytes nextPropId：第一个属性 ID
5 bytes labels（存储标签的 bitmap 或 token ID）
1 byte extra（是否为 supernode 的标识）

亮点： 点只保存第一条边和第一个属性，通过链式结构连接。

关系结构（34 字节）

字段 含义
1 byte 标识位（inUse、firstNode高位、nextProp高位）
4 × 7 bytes 起点/终点、前/后关系、属性ID、关系类型
1 byte 标记是否为起点/终点的第一条边（用于加速遍历）

亮点：

  • 每条关系都维护双向链表结构（前一条关系 / 后一条关系）
  • 通过关系链条，可以从任意一个点沿着其边关系不断向外遍历

属性结构（41 字节）

字段 说明
1 byte ID 高位
4 + 4 bytes 前后属性块 ID（组成双链表）
4 × 8 bytes 最多 4 个属性块（存储具体属性）

动态块机制： 如果属性值太大（如字符串、数组），就会引用 dynamic string/array block。

四、图遍历机制：免索引邻接（Index-Free Adjacency）

Neo4j 遍历步骤：

  1. 通过索引定位节点（一次性）

    MATCH (n:Person {name: "Alice"})

    这一步可能会用到 Lucene 或 B+ 树索引，找到节点ID。

  2. 直接通过ID × 15 定位到 nodestore.db

    固定偏移 = 定长记录大小 × ID，几乎是 O(1) 操作。

  3. 通过 nextRelId 跳转到边

    • 进入 relationshipstore.db，根据 ID × 34 定位。
    • 判断边类型，是否是我们要找的 KNOWS。
    • 获取终点节点 ID，继续跳边（通过 SN，SP，EN，EP）

特点：

  • 遍历从点开始 → 跳边 → 到点
  • 中间完全不需要通过索引查找关系
  • 遍历耗时仅与实际路径长度有关，不随图总规模增加！

这就是所谓的免索引邻接（Index-Free Adjacency）

五、图存储带来的规模和性能优势

项目 Neo4j 存储限制
节点 / 关系 ID 35 位（≈ 340 亿）
属性 ID 36 位（≈ 680 亿）
单节点边数量 支持百万级（DenseNode）

Neo4j 使用 定长记录 + ID 定位 + 关系链表 实现了：

  • 高吞吐写入（日志先行）
  • 快速图遍历（常数级别）
  • 高图规模（十亿级节点边）

六、总结与重点提炼

项目 说明
原生图存储结构 点、边、属性分别独立存储，定长记录结构
ID 定位机制 通过 ID × 记录大小 → 直接偏移访问，跳过索引
免索引邻接 关系链表连接每个点与其所有边，遍历完全靠链表，无需额外索引
存储优化技巧 属性使用动态块存储，边支持双向链表，超级节点专门标记优化
图遍历性能 O(1) 级别邻接查找 + O(k) 级边遍历（k为边数量）
